РАЗБОР ЭПИКРИЗОВ

Единый проект на основе переданных фронтенда, ML-модуля и REGEX_STAT.
Проверено на Python 3.12.14; синтаксис исходников рассчитан на Python 3.10 или новее. Интерфейс работает в браузере, модель — локально через llama-cpp-python.
Веса GGUF в сборку не входят.

УСТАНОВКА

Откройте терминал в каталоге проекта.

macOS / Linux:
    python3 -m venv .venv
    source .venv/bin/activate
    python -m pip install -r requirements-ml.txt
    cp .env.example .env

Windows PowerShell:
    py -3 -m venv .venv
    .venv\Scripts\python.exe -m pip install -r requirements-ml.txt
    Copy-Item .env.example .env

В Windows можно выполнять все следующие команды через .venv\Scripts\python.exe
вместо python, без активации окружения.

В .env укажите MODEL_PATH: абсолютный путь к существующему GGUF или путь
относительно каталога проекта. Исходный ML-модуль использовал
qwen2.5-3b-instruct-q4_k_m.gguf; имя в .env.example — пример, файл нужно получить отдельно.
MODEL_GPU_LAYERS=-1 включает доступное GPU-ускорение, MODEL_GPU_LAYERS=0 — CPU.
Поддержка GPU зависит от установленной сборки llama-cpp-python.
При установке этого пакета из исходников потребуется C/C++ toolchain.

ПРИЛОЖЕНИЕ С ЦИТАТАМИ

    python app.py

Откройте http://127.0.0.1:5000. Загрузите .md или ZIP с .md, нажмите «Обработать».
Интерфейс показывает прогресс фоновой задачи и ошибки по отдельным документам.
После обработки выберите файл: слева список, в центре 50 полей, справа исходный текст.
Наведение на значение с цитатой подсвечивает фрагмент, нажатие закрепляет его.
Повторное нажатие снимает закрепление. Экспорт: отдельный JSON, ZIP результатов или XLSX.

Для каждого документа в runtime/<сессия>/results/ сохраняются:
    <имя>.json         — только поля для кейсодателя;
    <имя>.ev.json      — значения, цитаты и позиции в исходном тексте;
    <имя>.report.json  — этапы обработки, изменения и предупреждения.
Таблица читает первый файл, подсветка — второй. Отчёты не попадают в экспорт полей.
Сводный отчёт пакета хранится в runtime/<сессия>/batch-report.json.

Пустое значение SECRET_KEY создаёт постоянный секрет сессии в runtime/.secret.
Не удаляйте его, если нужно сохранить доступ к существующим сессиям браузера.
Приложение рассчитано на один серверный процесс; очередь задач находится в памяти.
После перезапуска сервера незавершённую обработку нужно запустить заново.
По умолчанию сервер доступен только на текущем компьютере.

ТЕХНИЧЕСКИЙ ЗАПУСК БЕЗ ЦИТАТ

Поместите .md в test_docs. В сборке оставлен один пример из исходного ML-архива.

    python pipeline.py

Результат: test_json/<имя>.json. Каждый файл содержит 9 групп и 50 строковых полей.
Цитаты и служебные метрики в эти JSON не добавляются. Соответствующие старые
.json и .ev.json заменяются/удаляются перед повторной обработкой документа,
чтобы не оставить устаревший результат после ошибки. Файлы других документов не удаляются.

    python pipeline.py --input test_docs --output test_json --metrics reports/benchmark.json
    python pipeline.py --model /path/to/model.gguf

Все относительные пути настроек и аргументов считаются от каталога проекта.
Документы читаются из указанного каталога без рекурсивного обхода.
Код завершения: 0 — все документы обработаны; 1 — ошибки документов; 2 — ошибка запуска;
130 — остановка через Ctrl+C с сохранением промежуточного отчёта.

reports/benchmark.json содержит:
    total_seconds                         — время всей партии, включая обработку и запись;
    average_seconds_per_document          — общее время / начатые документы, включая неуспешные и прерванный;
    average_successful_document_seconds   — среднее время только успешных документов;
    records                               — время этапов, предупреждения и изменения по файлам;
    statistics                            — пропуски, количество, среднее, медиана, минимум и максимум.
Ленивая загрузка модели входит во время первого документа, которому потребовалась LLM.
Время установки зависимостей и подготовки конфигурации в замер не входит.
При остановке отчёт содержит interrupted=true, attempted и pending.
Для сдачи в каталог result, указанный в документе кейсодателя, используйте --output result;
по ТЗ интеграции стандартным выходным каталогом остаётся test_json.

ОТДЕЛЬНОЕ ДОБАВЛЕНИЕ ЦИТАТ

    python add_citations.py --input test_docs --results test_json

Команда читает готовые .json и создаёт/заменяет соседние .ev.json.
Она не переписывает значения полей. Этот дополнительный запуск не нужен для
технической сдачи; приложение выполняет обогащение цитатами автоматически.

РЕЖИМ БЕЗ МОДЕЛИ

Для работы только с правилами достаточно requirements.txt:
    python -m pip install -r requirements.txt
    python pipeline.py --regex-only
    python add_citations.py --regex-only

Для приложения установите LLM_ENABLED=false в .env. В интерфейсе и отчёте будет
явно указано, что LLM отключена. Это отдельный режим, его результаты не равнозначны
полному конвейеру. При LLM_ENABLED=true отсутствие весов возвращает ошибку,
автоматического переключения на правила нет.

АРХИТЕКТУРА

frontend/                 — HTML, CSS, JavaScript, подсказки к полям;
backend/app.py            — HTTP API и сессии;
backend/storage.py        — загрузки, каталоги документов и результатов;
backend/jobs.py           — очередь обработки и прогресс;
backend/exports.py        — JSON, ZIP и XLSX;
domain/                   — конфигурация, схема 50 полей, валидация и файловые операции;
extraction/regex/         — регулярки, разделённые по группам признаков;
extraction/consistency.py  — правила согласованности из REGEX_STAT;
extraction/statistics.py  — выбор полей для LLM и сводная статистика;
extraction/llm.py         — загрузка локальной модели и запросы;
extraction/prompts.py     — формат ответа и правила извлечения;
extraction/pipeline.py    — единая бизнес-логика обоих режимов;
extraction/evidence.py    — цитаты и соответствие позиций исходному тексту;
extraction/citation_candidates.py — отбор допустимых строк подтверждения;
app.py                   — запуск интерфейса;
pipeline.py              — консольный запуск без цитат;
add_citations.py         — самостоятельное обогащение готовых результатов.

Последовательность: регулярки → анализ пропусков и согласованности → LLM →
валидация результата → цитаты (только в приложении или отдельной команде).
LLM перечитывает подозрительные значения, поля с низкой уверенностью и пропуски
в контекстных полях исходного pipeline. Надёжные значения регулярных правил сохраняются.
Статистический этап использует эвристики из ноутбука, а не обученную статистическую модель.
Высокие глюкоза, давление или креатинин служат поводом перечитать текст;
на их основании диагноз автоматически не добавляется.
Генерация LLM ограничена JSON-схемой запрошенных ключей. При недопустимом или
пропущенном значении сохраняется результат правил с предупреждением. Известный препарат
другого класса не переносится в лекарственное поле (например, статин в иАПФ/сартаны).

Цитаты берутся из контекста найденного правила. Для оставшихся значений отбираются
допустимые строки; модель выбирает их номера либо null. Текст строки берётся дословно,
модель его не переписывает. Для бинарного 0 требуется явное отрицание нужного признака.
Если допустимых строк нет, дополнительный инференс не запускается. Принимаются только
однозначно найденные исходные фрагменты. Консервативный отбор может пропускать
нестандартные формулировки; полнота и медицинский смысл требуют отдельной проверки.
В .ev.json используются поля value, text, start, end, verified и method.
Позиции start/end — индексы символов Python, end не включается. API переводит их
в UTF-16 для JavaScript, поэтому подсветка не сдвигается из-за символов вне BMP.
verified означает точное совпадение текста цитаты с исходником, а не экспертную
проверку медицинского смысла. Отсутствие упоминания не снабжается выдуманной цитатой.
Если этап поиска цитат моделью завершился ошибкой, поля и цитаты регулярных правил
сохраняются, а предупреждение показывается пользователю.

HTTP API:
    GET    /files                 — список документов;
    POST   /upload                — multipart files (.md или .zip);
    POST   /process               — запуск обработки, ответ 202;
    GET    /process/status        — прогресс, ошибки и предупреждения;
    GET    /result/<имя.md>        — 50 полей;
    GET    /source/<имя.md>        — исходник и позиции для браузера;
    GET    /evidence/<имя.md>      — полный файл цитат;
    GET    /report/<имя.md>        — отчёт этапов;
    GET    /download              — scope=one|all, format=json|xlsx, name для scope=one;
    DELETE /files/<имя.md>        — удалить документ и результаты;
    DELETE /files                — удалить все документы и результаты сессии.

Загрузка принимает UTF-8 (включая BOM). До 2 МиБ на документ, до 64 МиБ на HTTP-загрузку
и распакованные тексты, до 1000 документов в сессии. Совпадающие имена при загрузке
получают суффикс. Пока идёт обработка, изменение набора документов запрещено.
