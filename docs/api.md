# HTTP API

Все пути относятся к одному origin. Сервер выдаёт подписанную cookie с идентификатором
сессии. Документы, прогресс и экспорт доступны только в соответствующей сессии.
HTTP-клиенту нужно сохранять cookie между запросами.

Маршруты находятся в `epicrises/web/routes.py`. Они обращаются к `DocumentService`,
`JobQueue` и `ExportService`; перевод внутренних цитат в координаты браузера выполняет
`web/citation_view.py`. Реорганизация модулей не меняет URL и форматы ответов.

## Документы

| Метод | Путь | Ответ |
|---|---|---|
| `GET` | `/files` | `{"files": [{"name": "case.md", "processed": true}]}` |
| `POST` | `/upload` | `{"accepted": ["case.md"], "skipped": ["readme.txt"]}` |
| `DELETE` | `/files/<name>` | `{"ok": true}` |
| `DELETE` | `/files` | `{"files": []}` |
| `GET` | `/result/<name>` | 50 строковых полей по схеме `epicrises/shared/field_schema.py` |
| `GET` | `/evidence/<name>` | Значения, цитаты и координаты в символах Python |
| `GET` | `/report/<name>` | Режим, время этапов, анализ, изменения и предупреждения |
| `GET` | `/source/<name>` | `{"text": "...", "citations": {...}}`, координаты UTF-16 |

`name` — имя из ответа `/files` или `/upload`, включая `.md`. Кодируйте его как
сегмент URL. Нельзя передавать путь к файлу за пределами сессии.

`POST /upload` принимает multipart-поля `files`, каждое — `.md` или ZIP.
Все документы проверяются до начала записи; некорректный текст отклоняет запрос целиком.
Файлы других типов попадают в `skipped`, каталоги и служебные записи `__MACOSX` игнорируются.
Совпадающим именам присваивается суффикс (`case_1.md`); расширение приводится к `.md`.
Повторная загрузка того же содержимого создаёт новый документ: дедупликации по хешу нет.

Ограничения:

- UTF-8, допускается BOM; пустые документы и нулевые байты отклоняются.
- 2 МиБ на документ.
- 64 МиБ на HTTP-запрос, включая multipart, и отдельно на распакованные документы.
- 1000 документов в сессии и 5000 записей в одном ZIP.
- Во время `queued`/`running` загрузка и удаление возвращают `409`.

`processed=true` означает наличие завершённого результата, а не успешную медицинскую
проверку. При неполной записи результат не выдаётся, но исходный текст остаётся доступен.

## Запуск обработки

`POST /process` выбирает только документы с `processed=false`. При ошибке одного
документа остальные продолжают обрабатываться. Следующий запуск повторяет только
документы без результата. Повторный POST во время активной задачи возвращает её прежний
`id`, не создавая новую задачу.

Пример ответа `202 Accepted`:

```json
{
  "id": "идентификатор-задачи",
  "status": "queued",
  "total": 2,
  "skipped": 3,
  "completed": 0,
  "succeeded": 0,
  "errors": [],
  "warnings": [],
  "first": null,
  "current": null,
  "mode": "regex-statistics-llm"
}
```

Фоновая задача может уже перейти в `running` или `done` к моменту следующего запроса.
`GET /process/status` возвращает текущее состояние:

| Поле | Значение |
|---|---|
| `status` | `idle`, `queued`, `running`, `done`, `failed` |
| `total` | Число документов, выбранных в этот запуск |
| `skipped` | Число ранее обработанных документов |
| `completed` | Число завершённых попыток, включая неуспешные |
| `succeeded` | Число успешно сохранённых результатов |
| `current` | Имя текущего документа или `null` |
| `first` | Первый успешно обработанный документ текущего запуска или `null` |
| `errors` | Массив `{file, error}` |
| `warnings` | Массив `{file, messages}` |
| `mode` | `regex-statistics` либо `regex-statistics-llm` |
| `seconds` | Время партии после успешного завершения очереди |
| `error` | Ошибка самой задачи при `failed` |

`done` означает, что все попытки завершились; в `errors` могут быть ошибки документов.
`failed` означает ошибку самой задачи, например записи сводного отчёта. Уже сохранённые
результаты остаются доступны.

Если все документы готовы, `POST /process` возвращает `200 OK` с `status=done`,
`total=0`, `completed=0`, `succeeded=0`, `skipped=N`, `seconds=0`. Модель и worker
не запускаются, файлы результатов не изменяются. Если документов вообще нет — `400`.

До первого запуска, после изменения набора документов и после перезапуска сервера
статус равен `{"status": "idle", "errors": [], "warnings": []}`. Признаки `processed`
при этом читаются из хранилища и сохраняются между перезапусками.

## Экспорт

`GET /download?scope=one|all&format=json|xlsx&name=<name>`

| Параметры | Результат |
|---|---|
| `scope=one&format=json&name=case.md` | JSON выбранного документа, `result.json` |
| `scope=all&format=json` | ZIP с `result/<имя>.json`, `results.zip` |
| `scope=one&format=xlsx&name=case.md` | XLSX выбранного документа |
| `scope=all&format=xlsx` | XLSX всех готовых документов, `results.xlsx` |

По умолчанию `scope=all`, `format=json`. Экспорт включает только значения, без цитат
и отчётов. Поля XLSX записываются текстом: даты, ведущие нули и формулоподобные строки
не преобразуются. Экспорт читает согласованный снимок уже завершённых результатов;
при обработке новой партии прежние результаты доступны.

## Ошибки

Ответ: `{"error": "описание"}`.

| Код | Причина |
|---|---|
| `400` | Некорректные параметры, документ или архив, пустая сессия при запуске |
| `403` | `Origin` POST/DELETE отличается от origin сервера |
| `404` | Исходный документ или завершённый результат отсутствует |
| `409` | Попытка изменить документы во время обработки |
| `413` | Превышен HTTP-лимит запроса |
| `503` | Модель не настроена либо не удалось поставить задачу в очередь |

Cookie имеет `HttpOnly` и `SameSite=Strict`. Это локальные сессии, без аккаунтов и ролей;
область применения и требования к сетевому размещению описаны в [System Design](system-design.md).

## Пример с curl

```bash
curl -c cookies.txt -b cookies.txt \
  -F 'files=@test_docs/example.md' http://127.0.0.1:5000/upload
curl -c cookies.txt -b cookies.txt -X POST http://127.0.0.1:5000/process
curl -b cookies.txt http://127.0.0.1:5000/process/status
curl -b cookies.txt 'http://127.0.0.1:5000/download?scope=all&format=json' -o results.zip
```

Замените `test_docs/example.md` на существующий путь. `cookies.txt` содержит ключ доступа
к сессии; не добавляйте его в репозиторий.
