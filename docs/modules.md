# Модули проекта

Код разделён по обязанностям: HTTP и интерфейс работают с документами и заданиями, конвейер извлекает данные, а доменные модули задают формат результатов. [System Design](system-design.md) описывает взаимодействие и ограничения компонентов.

## Точки входа

| Файл | Назначение |
|---|---|
| `app.py` | Загрузить `.env`, собрать Flask-приложение и запустить Waitress |
| `pipeline.py` | Разобрать аргументы CLI, проверить пути и запустить обработку каталога без цитат |
| `add_citations.py` | Добавить цитаты к существующим результатам без изменения значений полей |

Относительные пути настроек и аргументов разрешаются от корня проекта. Команды сохраняют свои прежние имена; повторяющаяся настройка модели и пакетная работа вынесены в `cli/`.

## Backend

| Модуль | Основные объекты | Обязанность |
|---|---|---|
| `backend/app.py` | `create_app()` | Настройки Flask, зависимости, регистрация маршрутов и обработчиков |
| `backend/sessions.py` | `session_id()`, `signing_key()` | Идентификатор браузерной сессии и постоянный ключ подписи cookie |
| `backend/http.py` | `documents()`, `register_http_handlers()` | Сервис текущего запроса, проверка Origin и перевод исключений в HTTP-ошибки |
| `backend/routes/documents.py` | Blueprint документов | Страница, список, загрузка, удаление, результаты и исходники |
| `backend/routes/processing.py` | Blueprint обработки | Запуск партии и чтение прогресса |
| `backend/routes/downloads.py` | Blueprint экспорта | Передача подготовленного файла браузеру |
| `backend/services.py` | `DocumentService`, `Download` | Сценарии работы с документами, запрет мутаций занятой сессии, сбор экспорта |
| `backend/uploads.py` | `read_uploads()`, `UploadBatch` | Проверка Markdown/ZIP до записи, ограничения размера и безопасные уникальные имена |
| `backend/storage.py` | `Storage` | Каталоги сессии, исходники, комплекты артефактов, готовность и поддержка старого формата |
| `backend/jobs.py` | `Jobs` | Очередь одного worker, отбор необработанных документов, повтор ошибок и прогресс |
| `backend/exports.py` | `build_json()`, `build_zip()`, `build_xlsx()` | Преобразование готовых результатов в байты выбранного формата |

`DocumentService` получает `session_id`, `Storage` и `Jobs` через конструктор. Он не читает Flask request/session, поэтому сценарии можно проверять отдельно от HTTP. Маршруты занимаются HTTP-контрактом; формат хранения остаётся внутри `Storage`.

В `create_app()` можно передать `pipeline` и `data_dir` для изолированных проверок. Очередь доступна через `app.extensions["jobs"]`; в тестах и при собственном управлении жизненным циклом используется `shutdown()` для ожидания завершения задач.

## Domain

| Модуль | Содержимое |
|---|---|
| `domain/config.py` | `Settings`, чтение настроек модели, корень проекта, разрешение путей |
| `domain/schema.py` | `GROUPS`, `KEYS`, обозначение отсутствующего значения и числовые диапазоны; 9 групп и 50 полей |
| `domain/validation.py` | Допустимые значения полей и проверка полной структуры результата |
| `domain/files.py` | Чтение UTF-8/BOM, выбор `.md` из каталога и атомарная замена JSON-файла |

Здесь нет зависимости от Flask, браузера или реализации очереди. Изменение схемы затрагивает не только таблицу интерфейса: должны оставаться согласованными извлечение, валидация, цитаты и экспорт.

## Извлечение

| Модуль | Обязанность |
|---|---|
| `extraction/pipeline.py` | Последовательность этапов и итоговый `Extraction(result, evidence, report)` |
| `extraction/review.py` | Нормализация результатов правил, копирование `Hit`, проверка и применение предложений LLM |
| `extraction/statistics.py` | Выбор полей для проверки и сводная статистика партии |
| `extraction/consistency.py` | Эвристики согласованности связанных медицинских признаков |
| `extraction/llm.py` | Ленивая загрузка GGUF, сериализация вызовов модели, общий JSON-контракт ответа |
| `extraction/prompts.py` | Запросы для проверки значений и выбора цитат |
| `extraction/evidence.py` | Поиск точных фрагментов, структура цитат и преобразование координат для браузера |
| `extraction/citation_candidates.py` | Отбор допустимых строк для модельного подтверждения значений |

Статистический этап использует правила и эвристики, а не обученную статистическую модель. `review` сохраняет результат правил, если ответ LLM недопустим, и возвращает предупреждение. Результат нормализации и проверки — копия исходных `Hit`, что позволяет отделять исходные свидетельства от изменённых значений.

### Правила извлечения

| Модуль в `extraction/regex/` | Содержимое |
|---|---|
| `document.py` | Нормализация текста и представление документа `Doc` с разделами |
| `core.py` | `Hit`, реестр `EXTRACTORS`, декоратор `ex()` и общие операции поиска |
| `engine.py` | Регистрация модулей, обход полей схемы, проверки диапазонов, связанные поля и группировка результата |
| `dates.py` | Даты поступления и выписки |
| `diagnoses.py` | Диагнозы и классификационные признаки |
| `examination.py` | Осмотр при поступлении |
| `ecg.py` | ЭКГ |
| `echo.py` | ЭХО-КГ |
| `radiography.py` | Рентген грудной клетки |
| `coronary.py` | Коронарография |
| `laboratory.py` | Лабораторные показатели |
| `medication.py` | Лекарственная терапия и классы препаратов |

Импорты предметных модулей в `engine.py` регистрируют обработчики в `EXTRACTORS`; это значимые импорты с побочным эффектом. Новый обработчик должен соответствовать ключу из `domain.schema` и возвращать `Hit` либо отсутствие результата. Текст цитаты берётся из документа, а не создаётся заново.

## Консольные сценарии

| Модуль | Обязанность |
|---|---|
| `cli/config.py` | Общие аргументы `--model`, `--regex-only` и настройки из `.env` |
| `cli/batch.py` | Последовательная обработка каталога, отчёт попыток, сохранение промежуточного отчёта при Ctrl+C |
| `cli/citations.py` | Проверка готового JSON и запись соседнего файла цитат |

Веб и CLI отличаются политикой запуска. Веб обрабатывает только незавершённые документы сессии. `pipeline.py` пересчитывает весь выбранный входной каталог; перед попыткой удаляет прежний JSON и файл цитат соответствующего документа. Это позволяет повторять эксперименты с новыми правилами и настройками.

CLI пишет плоские результаты `<stem>.json`, команда цитат — `<stem>.ev.json`. Эти каталоги самостоятельны и не являются внутренним хранилищем веб-сессии. Коды завершения пакетной обработки: `0` — успех, `1` — ошибки документов, `2` — ошибка запуска, `130` — прерывание с сохранённым отчётом.

## Frontend

Интерфейс использует нативные ES-модули без сборщика и сторонних браузерных библиотек. Шаблон подключает одну точку входа, которая собирает компоненты и передаёт им зависимости через параметры и callbacks.

| Файл | Обязанность |
|---|---|
| `frontend/templates/index.html` | Разметка страницы и подключение `app.js` |
| `frontend/static/app.js` | Сборка компонентов, начальная загрузка, запуск и сопровождение обработки |
| `frontend/static/api.js` | Единый HTTP-клиент, `ApiError`, запросы документов, загрузки и скачивания |
| `frontend/static/state.js` | Чистая функция расчёта количества готовых/ожидающих файлов и доступности действий |
| `frontend/static/files.js` | Список, выбор и удаление документов; защита от запоздавших ответов при переключении |
| `frontend/static/jobs.js` | Определение активной задачи, текст прогресса, опрос статуса раз в секунду |
| `frontend/static/upload.js` | Выбор файлов, отправка партии и ошибки загрузки |
| `frontend/static/results.js` | Таблица значений, состояния загрузки/отсутствия результата, связь с цитатами |
| `frontend/static/source.js` | Исходный текст, наведение и закрепление подсвеченной цитаты |
| `frontend/static/hints.js` | Подсказки по полям |
| `frontend/static/features.json` | Значение и пример каждого поля для подсказок |
| `frontend/static/save.js` | Область экспорта, формат, имя скачиваемого файла и сохранение Blob |
| `frontend/static/style.css`, `logo.svg` | Оформление и логотип |

Кнопка обработки доступна, когда есть хотя бы один необработанный файл и нет активной обработки, загрузки, удаления или проверки состояния. Сервер повторно проверяет это состояние независимо от браузера. HTTP-клиент возвращает `null` для ещё отсутствующего результата (404), а остальные ошибки передаёт интерфейсу.

Текст документов, имена и значения выводятся через текстовые DOM-операции. Таблица результатов и просмотр исходника согласуют закрепление цитаты через callback; глобальная шина пользовательских событий для этого не нужна.
