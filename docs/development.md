# Разработка

Все команды выполняются из корня репозитория. Для Python используется синтаксис версии 3.10 и новее. Frontend состоит из ES-модулей; сборка и `npm install` для приложения не требуются.

## Окружение и проверки без весов модели

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests -v
python -m ruff check .
python -m ruff format --check .
```

Автоматические Python-тесты используют правила или подменённые ответы модели. Для них не нужны GGUF-веса и установка `llama-cpp-python`. Для тестов frontend нужен Node.js с поддержкой встроенного `node:test`:

```bash
node --test tests/frontend/*.test.mjs
```

Это проверки функций и HTTP-клиента интерфейса, без запуска настоящего браузера. Изменения разметки, CSS и взаимодействия с DOM дополнительно проверяются вручную.

Для проверки отдельных подсистем:

```bash
python -m unittest discover -s tests -p test_jobs.py -v
python -m unittest discover -s tests -p test_extraction.py -v
python -m unittest discover -s tests -p test_citations.py -v
```

## Ручной запуск

Режим только с правилами запускает приложение без загрузки модели:

```bash
LLM_ENABLED=false python app.py
```

В браузере откройте `http://127.0.0.1:5000`. Основной регрессионный сценарий: загрузить A, обработать, загрузить B, обработать ещё раз. Вторая партия должна содержать только B, а результат и цитаты A должны остаться доступными. После обновления страницы готовые документы должны сохранять отметки обработки.

Для проверки пакетной команды без изменения поставляемых примеров результатов:

```bash
python pipeline.py --regex-only --input test_docs --output /tmp/epicrises-results --metrics /tmp/epicrises-benchmark.json
python add_citations.py --regex-only --input test_docs --results /tmp/epicrises-results
```

Проверку с настоящей LLM проводите отдельно: установите `requirements-ml.txt`, укажите локальный GGUF в `MODEL_PATH` и включите `LLM_ENABLED`. Веса загружаются при первом необходимом обращении к модели. `MODEL_THREADS` задаёт число потоков инференса, `MODEL_GPU_LAYERS` — использование GPU; этот режим не входит в быстрый цикл разработки.

## Как вносить изменения

### Изменить HTTP-сценарий

Логику операции добавляйте в `DocumentService`, преобразование запроса и ответа — в соответствующий Blueprint. Проверки загрузок находятся в `backend/uploads.py`, правила путей и готовности результатов — в `Storage`. Изменяющие операции должны проходить через проверку занятой сессии. Обновите [контракт API](api.md) и тест, демонстрирующий новое поведение.

Для тестового приложения передавайте временный `data_dir` и при необходимости подменённый `pipeline` в `create_app()`. Завершайте `app.extensions["jobs"].shutdown()` до удаления временного каталога, чтобы worker успел сохранить результаты.

### Изменить извлечение поля

Добавьте или исправьте правило в предметном модуле `extraction/regex/`. Проверьте положительный пример, отсутствие признака, явное отрицание и координаты цитаты, когда они применимы. Логику принятия ответа модели меняйте в `extraction/review.py`; подбор полей на проверку — в `statistics.py` и `consistency.py`.

При изменении самой схемы согласуйте `domain/schema.py`, `domain/validation.py`, обработчик поля, подсказку в `features.json`, запросы к модели и контрактные тесты. Текущий внешний контракт — 50 строковых полей; расширение схемы является отдельным изменением формата данных.

### Изменить очередь или хранилище

Сохраните правило: запись нового документа не инвалидирует готовые результаты остальных. Готовность определяется файлами, а не памятью процесса. Проверяйте вторую загрузку, повтор после ошибки, перезапуск очереди, параллельный `/process` и прерывание записи комплекта. Отдельно учитывайте старые плоские результаты и документы с именами вида `case.ev.md`.

Не увеличивайте число worker или серверных процессов без изменения модели координации: текущий `RLock` действует только внутри одного процесса. Требования к выделению worker описаны в [System Design](system-design.md).

### Изменить интерфейс

Запросы добавляйте в `api.js`, вычисление доступности действий — в `state.js`, представление прогресса — в `jobs.js`. UI-компоненты получают зависимости через параметры; их сборка остаётся в `app.js`. При переключении документов учитывайте порядок сетевых ответов: запоздалый результат не должен заменить текущий выбор.

### Проверить результат изменения

Запустите целевые тесты затронутой подсистемы, затем общие проверки перед передачей изменения. Для косметических правок достаточно линтера и просмотра затронутого интерфейса. Не включайте в тестовые примеры реальные персональные данные пациентов; коротких искусственных фрагментов достаточно для проверки контракта.

## Упаковка

```bash
python scripts/package.py
```

Архив создаётся рядом с каталогом проекта. Скрипт исключает `.env`, окружение, стандартный `runtime`, кэши, GGUF-веса и JSON из стандартных каталогов отчётов/результатов. Если рабочие данные размещены в другом каталоге внутри репозитория, учитывайте его отдельно при подготовке архива.
